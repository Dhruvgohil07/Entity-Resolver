## Context

`blocking/` landed and emits 84,117 candidate pairs on Abt-Buy carrying pair completeness
0.9928 (1.0000 on the test split). Nothing consumes them yet. `model/` needs feature vectors
and `cluster/` needs scored pairs from the model, so `features/` is the only stage that can
move — it is what turns a candidate pair into the ~25–35 numbers LightGBM will train on.

The target to beat is the TF-IDF baseline's **test F1 0.5204** (PR-AUC 0.4720), at
`test_fraction=0.3, seed=0`. `features/` cannot produce an F1 on its own, so this cut ships a
*diagnostic* report instead: per-feature discriminative power and coverage, so a dead or
mis-signed feature is caught here rather than blamed on the model a stage later.

Three prior measurements drive the feature choices and are not re-litigated:

- **Description must be its own signal, never concatenated onto the title.** Gluing it on drops
  test F1 0.5204 → 0.4349 and P@10 0.600 → 0.000, because Abt descriptions average 249 chars
  and Buy's 34 with 40% empty.
- **`brand` is `None` on every Abt record.** `brand_equal` will be dead on this dataset. It
  ships anyway, paired with an indicator, because that is exactly the case CLAUDE.md's
  missingness invariant exists for — and the report will show it as coverage 0.0000.
- **The two failure modes blocking cannot close** are a truncated marketplace title
  (`LG 1.6 cu.ft. Over the Range`) and disjoint vendor/distributor numbering. The first is
  what the cross title×description features below are aimed at; the second needs data this
  project does not have.

## Design

### Fit/transform, because some features are corpus-dependent

Pairwise-local features (a rapidfuzz ratio over two titles) are trivially serve-safe. IDF
weights and TF-IDF cosine are not — they are fitted artifacts. Mixing the two without a
boundary is how train/serve skew starts, so the featurizer is explicitly sklearn-shaped:

```python
featurizer = PairFeaturizer(include_semantic=False)
featurizer.fit(train_records)                     # train split only — never the catalog
matrix = featurizer.transform(train_records, train_pair_keys)
```

`fit` on the train split only, matching `eval/baseline.py`'s protocol exactly. Fitting IDF on
the full catalog scores better and is a quiet leak. `transform` takes packed int64 pair keys
from `blocking/pairs.py`, so the representation the blocking stage settled on carries through
unchanged.

### Modules

Mirrors `blocking/`'s shape — contract, families, assembly, CLI:

| file | holds |
| --- | --- |
| `features/base.py` | `FeatureSpec` (name, orientation, companion indicator) and `FeatureMatrix` (`values: np.ndarray`, `names: list[str]`); the `FeatureBlock` protocol |
| `features/string.py` | title/token/code/description similarity — the bulk |
| `features/numeric.py` | price and digit-token features |
| `features/semantic.py` | sentence-transformers cosine, lazy import, opt-in |
| `features/missingness.py` | the indicator helpers, and the rule that pairs them to imputed values |
| `features/vectorize.py` | `PairFeaturizer` — fit/transform, assembles every block in a fixed column order |
| `features/evaluate.py` | CLI → `reports/features.md` |

`FeatureSpec.higher_is_similar` exists because `price_abs_log_ratio` is inverted (lower means
more alike). The diagnostic negates those before computing PR-AUC; without the flag the report
would show an inverted feature as useless rather than as strong-and-flipped.

### The feature set (~32 columns)

**Title / text — `string.py`**: `title_ratio`, `title_token_sort_ratio`, `title_token_set_ratio`,
`title_partial_ratio`, `title_token_jaccard`, `title_token_containment` (|A∩B| / min — the
truncated-title case), `title_idf_overlap` *(fit)*, `title_tfidf_cosine` *(fit, `char_wb` 3-gram,
reusing `baseline.DEFAULT_ANALYZER` / `DEFAULT_NGRAM_RANGE`)*, `title_len_ratio`,
`title_common_prefix_ratio`.

**Vendor codes — `string.py`**: `model_number_exact` (on `model_number_key`),
`model_number_prefix_ratio`, `code_token_jaccard`, `code_token_shared_count`,
`code_best_partial_ratio`. Code tokens come from `normalize.code_key` — the same public rule
`blocking/standard.py:code_token_keys` uses. **No second implementation**; `standard.py` already
carried its own copy once and that is recorded as how train/serve skew starts.

**Description — `string.py`**: `desc_tfidf_cosine` *(fit)*, `desc_token_jaccard`,
`desc_len_ratio`, plus `cross_title_desc_cosine_max` / `_min` — A's title against B's
description and vice versa. That cross-signal is the one aimed squarely at the length asymmetry
that sank concatenation.

**Price and digits — `numeric.py`**: `price_abs_log_ratio`, `price_rel_diff`,
`digit_token_jaccard`, `digit_token_shared_count`.

**Brand — `string.py`**: `brand_equal`.

**Semantic — `semantic.py`**: `title_embedding_cosine`.

**Indicators — `missingness.py`**: `price_both_present`, `price_neither_present`,
`desc_both_present`, `desc_either_missing`, `brand_both_present`, `model_number_both_present`.

### Missingness is enforced by the registry, not by discipline

Every imputed feature declares `companion_indicator` on its `FeatureSpec`. One test walks the
whole registry and asserts no feature imputes without one — so a feature added later inherits
the check by being registered, the same way `blocking/`'s contract tests work by
parametrization. That is the mechanical form of CLAUDE.md's I5.

### Semantic is opt-in and offline-safe

`semantic.py` imports `sentence_transformers` lazily and checks for a cached model before
loading. Off by default in the CLI, behind `--semantic`. Its tests skip when the model is not
downloaded, so `pytest` stays hermetic and offline — the same convention the three existing
`data/raw/` tests use.

### Blocking runs inside each split

`split_by_entity(records)` first, then blockers on train records and test records separately,
then features per split. Cross-split pairs are all negatives by construction (entities were
assigned to one side), so this loses no positives. Pair indices stay split-local, which is what
keeps the packed-key convention valid.

Blocker parameters stay as committed. The known best-of-sweep bias in 0.9928 is noted in the
report, not fixed here.

## The report — `reports/features.md`

`python -m dedup.features.evaluate --dataset abt-buy --out reports/features.md`

One row per feature:

| feature | coverage | PR-AUC | pos mean | neg mean |
| --- | ---: | ---: | ---: | ---: |

- **coverage** — fraction of candidate pairs where the feature is defined (i.e. its companion
  indicator's mean). `brand_equal` will read 0.0000 here, and that is the point.
- **PR-AUC** — `average_precision(precision_recall_curve(...))` from `eval/metrics.py`, on the
  oriented value, with `n_positives_total` set to **every true pair in the split**, not the ones
  that survived blocking. So each number is capped by the inherited ceiling rather than
  flattered by pruning. `—` when coverage is zero.
- **pos mean / neg mean** — the separation, which catches a feature that ranks well but is
  constant, and a feature whose sign is backwards.

Headed with dataset, N, true-pair count, candidate count, the inherited union pair completeness
for that split, and the seed — same reproducibility rule the blocking table follows.

## Out of scope

Deliberately left for the commits after this one, and not silently dropped:

- **`data/__init__.py`'s untested registry.** `DATASETS` / `load_dataset()` are exercised only
  by the CLIs; a break would not fail `pytest`.
- **Re-selecting blocker parameters on train alone**, which is what would make 0.9928 a clean
  estimate rather than best-of-sweep.
- Any LightGBM training, calibration, or thresholding — that is `model/`.
