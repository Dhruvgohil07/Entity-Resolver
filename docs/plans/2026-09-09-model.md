## Context

`features/` turns a candidate pair into a 33-column vector, which unblocks the only stage that can
move: `cluster/` needs scored pairs from `model/`, and `service/` needs both. `model/` is also where
the first number comparable to the baseline's **test F1 0.5204** appears — nothing in
`reports/features.md` is that number.

Two design questions were settled by measurement in the preceding session and are already recorded
under CLAUDE.md **Project status > Open questions > Settled by measurement**. This plan implements
those decisions; it does not revisit them.

- **Calibration is out-of-fold over entity-grouped folds of train, with Platt, not isotonic.**
  Isotonic collapses the entire `p >= 0.9` region into one level (exactly 1.0), so a cost-derived
  auto-merge threshold has nothing to bite on inside a 253-pair atom. Out-of-fold gives the
  calibrator 777 positives against 230 and keeps all 1521 train records for the model.
- **Cost ratio `C_fm : C_fs : C_review = 20 : 2 : 1`**, giving `p_hi = 0.95` and `p_lo = 0.50` in
  closed form. Abt-Buy cannot validate the ratio — 27 of 18,819 candidates occupy the entire middle
  of the distribution — so it stays a parameter with a documented origin, never a tuned constant.

Intended outcome: `python -m dedup.model.evaluate --dataset abt-buy --out reports/model.md`
produces a committed report carrying the first honest F1 against the baseline, the calibration
quality behind it, and the band occupancy the cost model implies.

## Approach

### Step 0 — two shared helpers, so `model/` does not import from a CLI

`features/evaluate.py:120` defines `block()`, and `blocking/evaluate.py:47` defines
`default_blocker_set()`. `features/evaluate.py` already imports the latter out of a CLI module;
`model/` would make that a third consumer, and `service/` a fourth.

- **New `src/dedup/blocking/defaults.py`** (library, no argparse): move `default_blocker_set()`
  here verbatim, and move `block()` here as `block_split(records) -> tuple[BlockerRun, BlockerScore]`.
  Re-export from `blocking/evaluate.py` and `features/evaluate.py` so existing imports and tests
  keep working.
- **`src/dedup/eval/splits.py`** — add `kfold_by_entity(records, *, n_folds=5, seed=0) ->
  list[list[Record]]`, built on the existing `group_by_entity`. It belongs beside
  `split_by_entity` because `eval/` is where the splitting invariant is enforced, and `cluster/`
  will need grouped folds too.

*Fallback if this refactor is unwanted:* `model/` imports `block` from `features.evaluate`, which
follows the precedent already in the tree. One-line change, no other part of the plan moves.

### Step 1 — `model/threshold.py` (no data dependency, lands first)

Pure closed-form derivation of the two thresholds from the cost ratios.

```python
@dataclass(frozen=True)
class CostModel:
    false_merge: float = 20.0   # C_fm, in units of one review action
    false_split: float = 2.0    # C_fs
    review: float = 1.0         # C_review — the unit
    # __post_init__ rejects non-positive costs and an empty review band:
    #   review * (1/false_merge + 1/false_split) >= 1  ->  ValueError
    auto_merge_threshold  = 1 - review / false_merge   # p_hi
    auto_reject_threshold =     review / false_split   # p_lo

class Band(str, Enum): AUTO_MERGE / REVIEW / AUTO_REJECT

def assign_bands(probabilities, cost) -> np.ndarray
def band_summary(probabilities, labels, cost) -> BandSummary   # counts, false merges,
                                                               # missed pairs, queue size,
                                                               # realized expected cost
```

The empty-band check is not defensive padding: `20 : 1 : 1` gives `p_lo` 1.0 against `p_hi` 0.95, so
the constraint bites at plausible-looking values. Boundary convention is `>=`, matching
`evaluate_at_threshold` in `eval/metrics.py:192`.

### Step 2 — `model/train.py`

```python
DEFAULT_PARAMS = dict(n_estimators=300, learning_rate=0.05, num_leaves=31,
                      min_child_samples=20, verbose=-1)

@dataclass(frozen=True)
class PairScorer:
    featurizer: PairFeaturizer          # fitted
    booster: LGBMClassifier
    calibrator: PlattCalibrator | None
    def raw_scores(records, pair_keys) -> np.ndarray
    def probabilities(records, pair_keys) -> np.ndarray   # raises if calibrator is None

def train_scorer(records, *, params=DEFAULT_PARAMS, include_semantic=False, seed=0) -> PairScorer
```

`PairScorer` bundles the featurizer with the booster deliberately — a model artifact that does not
carry its own fitted featurizer is train/serve skew waiting to happen, which CLAUDE.md names as a
class of bug rather than a preference.

**No class reweighting.** Post-blocking imbalance is ~60:1, not the thousands the general case
assumes, and a reweighted booster is deliberately miscalibrated — it would have to be undone by the
calibrator it feeds. Documented in the module docstring so it is not "fixed" later.

Hyperparameters stay fixed and documented. Tuning is out of scope for this landing and would need
an inner split; tuning against test is the leak this whole protocol exists to avoid.

### Step 3 — `model/calibrate.py`

```python
class PlattCalibrator:            # thin wrapper over LogisticRegression(C=1e10)
    def fit(p, y) -> Self
    def transform(p) -> np.ndarray

def out_of_fold_scores(records, *, n_folds=5, seed=0, params=...) -> OutOfFoldScores
def fit_calibrated_scorer(train_records, *, n_folds=5, seed=0, ...) -> PairScorer
```

`out_of_fold_scores` takes raw `Record`s, folds them with `kfold_by_entity`, then for each fold
normalizes, blocks and **refits the featurizer on the other folds only** before scoring the held-out
fold. Refitting the featurizer per fold — not just the booster — is the load-bearing detail: the
fitted IDF weights are part of the feature definition (`vectorize.py:127` says so in its own error
message), so a featurizer fit once over all of train leaks held-out text into the calibration set.

`fit_calibrated_scorer` then trains the final booster on **all** of train and attaches the
calibrator fitted from the out-of-fold predictions.

### Step 4 — `model/evaluate.py` (CLI → `reports/model.md`)

Mirrors `eval/baseline.py` exactly: frozen `ModelReport`, `evaluate(...)`, `render_markdown(...)`,
`main(argv)` with `--dataset --root --test-fraction --seed --folds --semantic --out` plus
`--cost-false-merge / --cost-false-split / --cost-review`.

**Two operating points are reported, and both are needed:**

1. **Best-F1 threshold chosen on train, spent on test.** This is the protocol
   `eval/baseline.py:run_variant` uses, so it is the only like-for-like comparison against the
   baseline's 0.5204.
2. **The cost-derived bands.** This is what the system actually does, and it is not an F1 — it is
   three band populations and a realized cost.

Report sections: Setup · Results (both operating points) · Calibration quality (Brier, ECE,
reliability bins, raw against calibrated) · Band occupancy plus a cost-ratio sensitivity table ·
LightGBM gain importance cross-checked against `reports/features.md`'s univariate ranking ·
**Reading this honestly**, which must state that blocking has already discarded ~96% of pairs so
precision is not comparable to the baseline's un-blocked precision, that the cost ratio is not
validated by this dataset, and that 56 true pairs are auto-rejected with 35 of them below p=0.01.

### Step 5 — tests

`tests/test_model_threshold.py` — closed-form values; `20 : 1 : 1` raises; non-positive costs raise;
raising `C_fm` raises `p_hi` (monotonicity); boundary lands in the merge band; `expected_cost`
charges a false merge `C_fm` and a missed pair `C_fs`.

`tests/test_model_calibrate.py` — the leak tests, which are the point of this file:
- **no entity spans two folds**, and the folds partition the records exactly;
- **the featurizer is refit per fold** — build a fold whose held-out text carries a token absent
  from every other fold, assert that token is not in the vocabulary that scored it;
- Platt is monotone, so PR-AUC is unchanged by calibration (calibration must not be able to flatter
  the ranking metric);
- calibration lowers ECE on a deliberately miscalibrated input.

`tests/test_model_train.py` — `probabilities` raises when the calibrator is absent; column order
matches `featurizer.names`; an empty pair set returns empty; identical output for a fixed seed.

`tests/test_model_evaluate.py` — report names every band and the cost model; the recall denominator
is every true pair in the split, not the survivors (mirroring
`test_a_missed_positive_lowers_pr_auc`); plus integration tests marked
`@pytest.mark.skipif(not REAL_DATA.is_dir(), ...)` that re-derive the headline test F1 and assert it
beats the baseline's 0.5204.

Acceptance:

- Test F1 at the train-chosen threshold **beats 0.5204**, and the report states the blocking caveat
  rather than claiming a clean win. The throwaway probe put this near 0.88; anything far below that
  means something regressed, anything far above means a leak.
- `CostModel()` yields exactly `p_hi = 0.95`, `p_lo = 0.50`.
- Calibrated ECE is below the uncalibrated ECE on test, and PR-AUC is unchanged by calibration.
- `pytest -rs` shows the pre-existing skips only — one semantic, and the data-gated ones when the
  benchmark is absent — with no new unconditional skips.

  history recommends: it caught the `FILL_VALUE` reporting bug in `features/` that the test suite
