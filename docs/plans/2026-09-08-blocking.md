## Context

`blocking/` is stage 3 and the only stage that can currently move: `features/` needs candidate
pairs, `model/` needs those vectors, `cluster/` needs scored pairs. Everything it consumes now
exists — labeled records with `entity_id`, `normalize()`, the entity-grouped split, and metrics
that already refuse to reward pruning.

It matters more than the stages after it. Comparing all pairs is `N²` — 2,359,878 pairs for
Abt-Buy's 2,173 records, and ~20 billion at the 200k records `synth/` will produce. Blocking
discards almost all of them, and **any true pair it discards is unrecoverable**: the classifier
never sees it, so no model work brings it back. Blocking sets a hard ceiling on system recall.

Outcome: `python -m dedup.blocking.evaluate` produces `reports/blocking.md` — a blocker × pair
completeness × reduction ratio table whose `union (all)` row is the recall ceiling the rest of
the pipeline inherits.

### Measurements that drive this design

Taken during planning against the real benchmark (2,173 records, 1,118 true pairs):

| blocker | candidates | PC | RR |
|---|---:|---:|---:|
| standard — code-like tokens | 2,072 | 0.6708 | 0.9991 |
| standard — rare token df≤30 | 29,555 | 0.8694 | 0.9875 |
| sorted_neighborhood w=20 | 41,097 | 0.6190 | 0.9826 |
| lsh — MinHash token shingles t=0.4 | 27,828 | 0.5894 | 0.9882 |
| ann — faiss HNSW k=10 | 14,604 | 0.9562 | 0.9938 |
| **union (all five)** | **84,122** | **0.9928** | **0.9644** |

Three findings:

1. **Exact model-number keys fail on punctuation.** `KXTS208W` (Abt) vs `KX-TS208W` (Buy) is the
   same Panasonic phone. Stripping separators lifts that blocker from PC 0.3354 → 0.5349.
2. **`ann` alone (0.9562) beats every key-based blocker combined.** `standard` + `ann` reach
   PC 0.9776 with 15,582 candidates — 98% of the achievable ceiling at a quarter of the cost.
3. **`lsh` contributed exactly zero marginal PC** (+20,539 candidates, PC unchanged at 0.9884).
   Product titles are short, so token-shingle MinHash has little to work with. This is one
   untuned config, which is why it gets built and measured rather than assumed away.

## Approach

### 1. `normalize.py` — add `model_number_key`

Additive only. `model_number` keeps returning the printed vendor code (`KX-TS208W`); a new
`NormalizedRecord` field `model_number_key: str | None` holds the lowercased, separator-stripped
form (`kxts208w`). Computed in `normalize()` so batch and serve cannot diverge, and so `features/`
inherits it later without importing from `blocking/`.

Existing `_extract_model_number` and all its tests are untouched.

### 2. Pair representation

Blockers return `numpy` int64 arrays of packed pair keys (`i * n + j`, always `i < j`), not sets
of tuples. Union and dedup are `np.unique` over the concatenation; unpack with `divmod`. A Python
set of tuples costs ~2–3 GB at synth scale — this costs ~8 bytes per pair and keeps the same code
working when `synth/` lands.

Helpers live in `blocking/pairs.py`: `pack(i, j, n)`, `unpack(keys, n)`, `union(*arrays)`.

### 3. Blocker modules

Common shape — a small class with `name`, `params` (a string for the report), and
`pairs(records: list[NormalizedRecord]) -> np.ndarray`:

- **`standard.py`** — exact-key blocking over a pluggable key function, plus the three key
  functions measurement justified: `model_number_key`, code-like title tokens, and rare tokens
  (document frequency ≤ cutoff). Buckets larger than a `max_block_size` are dropped, not expanded
  — one runaway block silently costs more than every other blocker combined.
- **`sorted_neighborhood.py`** — sort on a key, slide a window of `w`.
- **`lsh.py`** — `datasketch` MinHash-LSH. Shingle mode is a parameter (token vs character), since
  the zero-contribution result above came from token shingles on short titles.
- **`ann.py`** — `faiss.IndexHNSWFlat` over the TF-IDF matrix, `METRIC_INNER_PRODUCT` on
  L2-normalized rows so inner product is cosine. Reuse the vectorizer construction from
  `src/dedup/eval/baseline.py:fit_vectorizer` rather than re-deriving the char-3gram config.
- **`union.py`** — concatenate and `np.unique`. Its PC is the number that matters.

### 4. `evaluate.py` — the measurement contract

Per the `blocking-eval` skill:

- **PC** = true pairs in candidates ÷ **all** ground-truth pairs. The denominator comes from
  `dedup.eval.splits.count_true_pairs` (already exists, already counts the transitive pairs —
  1,118 on Abt-Buy, not the 1,097 the mapping file ships). **Assert** the denominator equals it;
  computing PC over survivors makes it identically 1.0, which the skill flags as a bug that has
  fooled published papers.
- **RR** = 1 − candidates ÷ (N(N−1)/2). Report the absolute candidate count beside it — at synth
  scale RR 0.999 still leaves 20M pairs for `features/` to compute.
- **Never** emit precision, recall-of-non-pairs, F1 or accuracy for a blocker. Discarding
  non-duplicates is the job, not an error.
- Table headed with dataset, N, ground-truth pair count and seed; one row per blocker; a mandatory
  `union (all)` row; build and query seconds per blocker.
- **Report which true pairs the union misses**, with ~10 worked examples showing both titles. That
  missed set is where the next blocker's design comes from. Classification into failure modes stays
  prose written from the examples — not an automatic classifier.

**Parameter rule:** any parameter chosen by looking at PC (window `w`, `k`, df cutoff, LSH
threshold) is chosen on the **train** split via `dedup.eval.splits.split_by_entity`, then reported
on the full catalog. The report states which parameters were tuned and on what.

### 5. Reuse, not reinvention

- `dedup.eval.splits`: `count_true_pairs`, `group_by_entity`, `split_by_entity`
- `dedup.normalize`: `normalize`
- `dedup.data`: `load_dataset`, `DATASETS` — so `evaluate.py` takes `--dataset` and never imports
  a loader
- `dedup.eval.baseline`: `fit_vectorizer` for the `ann` vectorizer

Do **not** import `sklearn.metrics` — the eval package exists because sklearn's recall denominator
is wrong for a pruned candidate set.

### 7. Tests

- Every blocker returns unique upper-triangle pairs (`i < j`, no duplicates, no self-pairs).
- Every blocker is deterministic across runs and independent of input row order.
- A known-duplicate pair from the committed fixtures is caught by the blocker that should catch it.
- **Regression:** PC computed over survivors instead of all ground truth must fail loudly — the
  same class of defect the audit caught in `precision_at_k`.
- `max_block_size` actually caps a runaway block.
- Real-benchmark test pinning union PC in a band, skipped when `data/raw/` is absent (matching
  `tests/test_eval_baseline.py`).
